Featured project / Operational software

M.A.D. Meas Admin Dashboard

Windows desktop application

A clearer view of
what’s running.

The automation was already doing important work. Understanding it, supporting it, and finding what needed attention was the harder part.

The problem. Scheduled jobs, scripts, and logs were spread across different places. Tracing what ran, which scripts it used, and where to look when something failed took too much digging.

What I built. A desktop application that brings scheduled tasks, scripts, dependencies, and logs into one searchable workspace. It also provides file monitoring and tools for adding consistent error handling.

The result. One place to follow the automation from task to script to log, making day-to-day support and troubleshooting easier.

Find the connections

Search tasks and scripts together, see their links, and organize the view around the work.

See what happened

Inspect script content, logs, and file-processing history without hunting through folders.

Make controlled changes

Preview logging and error-handling changes before applying them, with separate admin and read-only roles.

More about the application +

The application reads live Windows scheduled tasks and discovers their linked scripts. Re-importing refreshes the catalog while preserving user-edited descriptions and manual links.

FileWatcher starts processing when files arrive, records run history, and provides watchdog recovery and alerts for files that remain unprocessed. Configurable tools prompt for parameters before execution and remember the last-used values.

Each user can save their own column layout and grouping. Administrators can manage tasks and access, and review a diff before applying script changes.

02 / File processing

When the file arrives,
the work starts.

The problem. File workflows waited for scheduled checks, and failures were difficult to trace.

What I built. Event-driven monitoring where appropriate, with run history, recovery, and alerts for stuck files.

The result. Files could be processed on arrival, with better visibility when something went wrong.

Under the hood +

File monitoring, execution history, structured logging, watchdog recovery, and stuck-file alerts replaced polling where it suited the workflow.

03 / Practical AI

Useful answers from
scattered knowledge.

The problem. Finding and applying knowledge across documentation, data, and internal tools took too much manual effort.

What I built. A local AI assistant grounded in curated documentation, with controlled, read-only tools.

The result. Internal knowledge became easier to access while sensitive operations stayed controlled.

Under the hood +

Curated references, tool routing, auditability, and explicit guardrails. AI handled language; deterministic tools handled operations that needed predictable behavior.
